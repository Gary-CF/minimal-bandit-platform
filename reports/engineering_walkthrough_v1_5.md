### 0:00–1:15：开场

“这个项目研究平稳随机多臂老虎机：每轮只能选一个臂，看到被选臂的一次奖励；各臂的真实均值未知，我要在探索和利用之间权衡，让长期累计损失尽量小。

我做了两种环境：Bernoulli 奖励是 0/1，Gaussian 是连续奖励。v1.0 先完成四个策略与可复现实验闭环，v1.5 增加六个策略，现在共有十个策略实现，包含 Random 基线。它们不是十个互不相关的脚本，而是通过同一个接口接入实验框架。

目前十策略、263 项测试以及 Bernoulli/Gaussian 三组正式实验已完成，420 次运行和结果完整性检查通过。”

不要把 GaussianBandit 说成算法，也不要把当前项目说成 contextual 或 non-stationary bandit。

### 1:15–3:00：用一轮操作解释整个架构

打开 `BanditAlgorithm` 的两个方法：

```python
action = algorithm.select_action()
reward = env.step(action)
algorithm.update(action, reward)
instant_regret = env.pseudo_regret(action)
```

“算法维护自己的学习状态并输出一个臂编号。环境根据该臂的真实分布抽一次奖励，算法只拿到这个编号和奖励。runner 再做统计和保存。这样添加算法时不用修改环境，换环境也不用重写实验循环。

环境知道真实均值，因为它要模拟数据；runner 知道真实均值，因为它要评估。算法没有收到真实均值，所以没有偷看答案。”

例子：均值 `[0.2,0.5,0.7]`，选臂 1 后恰好得到 reward=1，学习端将这次 1 计入臂 1；评估端记录 regret=0.7−0.5=0.2。一次奖励很好，仍不表示这次动作在期望意义上最优。

### 3:00–4:30：先讲最容易理解的探索方式

“Random 每轮均匀选臂，作为不会学习的参照。ε-Greedy 以 ε 概率均匀探索，剩下时间选经验均值最大的臂；当前 ε 固定为配置值。ETC 则把探索与利用分成两个阶段：每个臂先采 m 次，然后锁定探索阶段经验均值最高的臂。

它们让我看到两个不同的成本：ε 太大会长期浪费在探索上，太小会过早相信不准确的均值；ETC 的 m 太小容易锁错，太大又消耗预算。当前 ETC 锁定后虽然还更新统计，但不再换臂。”

### 4:30–7:00：把四种 UCB 讲成同一个问题的四种回答

“UCB 不需要抛硬币决定是否探索，它把一个臂的评分写成‘经验均值加潜在提升空间’。样本少，潜在空间大；被观察多了，空间缩小。

UCB1 用样本量和时间构造半径。UCB-V 再利用经验方差，低方差可能让界更紧，但它还有早期较大的范围修正项。MOSS 使用总预算 T，减少在预算有限时过度探索；所以它不是完全不需要知道未来预算的算法。KL-UCB 针对 Bernoulli 分布，用 KL 约束求仍可能成立的最大均值，而不是统一加一个对称半径。

这四个算法的主要工程状态都是计数、奖励和、经验均值；UCB-V 多记平方和，KL-UCB 多了数值二分求界。”

现场展开 UCB1 一个公式即可，其余可指公式表，不必在 15 分钟里证明 regret 界。

### 7:00–9:00：后验采样与 Gaussian 假设

“TS 的不确定性用一个分布表示。Bernoulli TS 为每个臂维护 Beta 后验：成功加 alpha，失败加 beta；每轮从每个后验抽一个可能的均值，然后选最大者。

Gaussian TS 的未知量仍是均值，但观测噪声方差假设已知，先验和后验都为正态。数据多时后验方差下降，均值也更受数据影响。Gaussian UCB 则把已知标准差乘到置信半径上。

当前环境可以异方差，但 Gaussian TS 类只接收一个公共观测方差；因此标准演示使用同方差环境。标准差和方差必须分清：std=2 对应 noise_variance=4。”

### 9:00–11:15：为什么它是实验平台

“JSON 固定环境、算法参数、horizon 和 seeds。字符串形式算法会转为统一字典，工厂负责把不同参数传给相应类。MOSS 的 T 由本次 horizon 注入，保证多 horizon 调度时不会一直用旧预算。

每个组合都重新实例化环境和算法。同一个根 seed 派生两个 RNG，一个采环境噪声，一个做算法随机选择，避免算法多抽一个随机数就把环境噪声序列也挤掉。

每轮保存动作、奖励、单步和累计 pseudo-regret，配置快照单独保存。分析阶段读取 CSV，不把画图和训练混在一起。普通 runner 的结果目录能拒绝不同配置混用；正式 suite 另外保存源码和依赖指纹，并拒绝同名算法在同一个配置里做参数扫描。”

### 11:15–13:15：拿证据说话

“当前原有 263 项测试通过。针对正常路径，又对 13 种合法环境—策略组合做了短预算和重复 seed 检查；这不是性能排名，只是运行与可复现性验证。

旧版 easy-gap 和 hard-gap 各有十个 seed；另有三个 horizon。Random 的理论期望损失能直接算出来，用来检查环境、regret 和聚合是否接通。

旧 easy-gap 中 TS 的平均最终 regret 是 13.76，UCB1 是 81.8；这说明指定配置下的现象，不能推出 TS 永远最好。UCB-V 的方差优势可能被早期修正抵消；hard-gap 虽然更难识别，但每次选错损失更小，绝对 regret 不必更高。”

### 13:15–15:00：诚实说明边界，展示自己懂工程

“这次发布修复了同名算法参数扫描覆盖 CSV 的问题，增加了整个 batch 的预校验，并收紧 Gaussian 数值和噪声模型约定。

## 二、统一符号：先把所有公式放到同一坐标系

K：臂数；T：本次总预算；t：当前待选择轮次。选择前，N_i 是臂 i 已观测次数，S_i 是奖励和，经验均值为 `S_i/N_i`。当前轮 reward 到来后才更新这些量。

多数均值类策略的更新是：

$$N_i\leftarrow N_i+1,\quad S_i\leftarrow S_i+x,\quad \hat\mu_i\leftarrow S_i/N_i.$$

也可以用增量均值更新，但当前实现多数显式保留奖励和，便于检查 `reward_sums` 与 runner 记录是否一致。每个策略通常保存 O(K) 状态；runner 把 T 行记录全放在内存，日志内存为 O(T)。

## 三、十个算法逐个复习

### 1. Random：不会学习的刻度尺

`rng.integers(K)` 均匀选一个臂，`update` 不做任何事。不需要估计均值。

$$\mathbb E[R_T]=T\left(\mu^\star-\frac1K\sum_i\mu_i\right).$$

对 `[0.2,0.5,0.7]`，每步期望损失约 0.2333，T=5000 时约 1166.67；旧实验均值 1161.03。这是带抽样波动的 sanity check，不要求恰好相等。算法选臂 O(1)，自身不保留每臂统计。

### 2. 固定 ε-Greedy：显式随机探索

先抽 `x=rng.random()`；若 x<ε，则均匀随机选臂，否则 `argmax(estimated_reward)`。注意 ε 是进入随机分支的概率，不是选择次优臂的概率，随机分支也可能选中最优臂。

若最优臂唯一，即使已识别它，随机分支仍产生每步期望损失 `ε × 平均 gap`。固定正 ε 因而保留线性累积的探索成本，不能把递减 ε 版本的性质直接搬给当前实现。

状态名是 `reward_sum`、`estimated_reward`，与 UCB1 的复数字段不同。ε=0 时不会主动随机探索，初始全 0 且并列取最小索引，可能停留在早期选中的臂。选臂 O(K)（利用分支），更新 O(1)。

### 3. ETC：把探索预算一次分配好

参数 m=`exploration_rounds_per_arm`。前 Km 次行动循环 `0,1,…,K−1`；之后固定 `committed_arm=argmax(estimated_mean)`。

例：K=3、m=2，则探索动作是 `[0,1,2,0,1,2]`。若 T=6，实验结束时 `committed_arm` 仍为 None，因为第 7 次选臂尚未发生；T=7 才进入锁定阶段。这不是少执行一次 update。

锁错的风险不能靠后续更新自动修正，因为策略不会重新比较并换臂。固定小 m 不保证任意长 T 下取得次线性损失。现有 `select_action` 每次都求 `counts.sum()`，因此实现上的单次成本为 O(K)，即使已经锁定；不要仅根据 ETC 的概念把当前实现说成全程 O(1)。

### 4. UCB1：均值加乐观半径

初始化先依次采每个臂，避免分母为零。之后：

$$I_i(t)=\hat\mu_i+\sqrt{\frac{2\log t}{N_i}},\qquad A_t=\arg\max_i I_i(t).$$

例如同为均值 0.5，N=2 的臂比 N=100 的臂评分更高，因为前者还没有被充分观察。探索由评分自发产生，不是额外随机挑一个臂。

源码的 t=`counts.sum()+1`，与“已经完成轮数”相差 1。当前仅允许与 Bernoulli 环境配合，不能直接无条件用到无界 Gaussian 奖励。选臂 O(K)，更新 O(1)。

### 5. UCB-V：把“波动多大”也学出来

额外记平方和 Q_i，计算：

$$\hat V_i=\max\{Q_i/N_i-(S_i/N_i)^2,0\}.$$

这是分母 N_i 的经验二阶中心矩，不是分母 N_i−1 的无偏样本方差。max 是为了避免浮点消减造成微小负数。

源码评分为：

$$I_i=\hat\mu_i+\sqrt{\frac{2\hat V_i\ell}{N_i}}+\frac{3b\ell}{N_i},\qquad \ell=\log\max\{\textstyle\sum_jN_j,2\}.$$

b=`reward_range`，Bernoulli 应取 1。该实现的 log 使用已经完成的轮数，与 UCB1 的 t 定义略有差别，解释时应保留这个实现事实。即使方差为 0，范围修正仍非零；它防止少量样本恰好相同时过度自信，也可能令早期探索比较保守。选臂 O(K)，更新 O(1)。

### 6. MOSS：把总预算放进探索奖励

$$I_i=\hat\mu_i+\sqrt{\frac{\max\{\log(T/(KN_i)),0\}}{N_i}}.$$

当 N_i≥T/K 时，对数部分被截成 0，这个臂不会继续从这项获得探索奖励。这里体现了“预算只有这么多，不能所有臂都无限追求很小的不确定性”。

与 UCB1 比较时要注意 MOSS 知道 T。多 horizon 实验不是只把一条长曲线截断：不同 T 会从评分上改变决策。runner 每次调用工厂时传入当前 horizon，正是为了保持此契约。选臂 O(K)，更新 O(1)。

### 7. KL-UCB：求一个与数据还不矛盾的最大均值

Bernoulli KL 散度：

$$d(p,q)=p\log\frac pq+(1-p)\log\frac{1-p}{1-q}.$$

这里 p 是经验成功率，q 是候选真实均值，不是两个奖励样本。评分是满足下式的最大 q∈[p,1]：

$$N_i d(\hat\mu_i,q)\le \log t+c\log\max\{\log t,1\}.$$

分布参数靠近 0 或 1 时，用 Bernoulli 自身的分布差异描述不确定性，比一律采用对称半径更贴合模型。源码 `kl_ucb_bound` 在 `[p,1]` 二分 40 次：满足预算则把左边界右移，不满足则缩右边界，最终返回左边界。

c 默认 3、允许 0；helper 已补齐 q=0/1 端点：同分布 KL=0，支持不匹配时 KL=正无穷；二分 budget 要求有限非负数。选臂 O(40K)，更新 O(1)。

### 8. Beta–Bernoulli TS：每轮抽一个可能的世界

每臂独立先验 Beta(1,1)，即成功率在 [0,1] 上的均匀分布。看到成功/失败后：

$$\alpha_i\leftarrow\alpha_i+x,\qquad\beta_i\leftarrow\beta_i+1-x.$$

选择时抽 `θ_i ~ Beta(α_i,β_i)`，取最大者。采的是“可能的成功率”，不是下一次 0/1 奖励。

例如成功 3 次、失败 1 次，后验为 Beta(4,2)，后验均值为 4/6。样本很少的臂后验较宽，偶尔抽到高值而获得探索机会，所以无需额外 ε。

检查式：`alpha−1=成功次数`、`beta−1=失败次数`、`alpha+beta−2=选择次数`。选臂 O(K)，更新 O(1)，不强制先访问全部臂。

### 9. Gaussian UCB：已知噪声越大，越不能轻信均值

观测模型 `X_i ~ N(μ_i,σ²)`，未知的是 μ_i，σ 作为输入已知：

$$I_i=\hat\mu_i+\sigma\sqrt{\frac{2\log t}{N_i}}.$$

均值相同、样本数相同，σ 越大，半径越大。`known_std` 是标准差，不是方差。当前只接收一个标量；预校验要求它覆盖所有臂的标准差，同方差时可精确匹配，异方差时是保守共同上界。选臂 O(K)，更新 O(1)。

### 10. Gaussian TS：精度加权的后验更新

先验 `μ_i ~ N(m₀,v₀)`，条件观测 `X|μ_i ~ N(μ_i,σ²)`。N_i 次观测、奖励和 S_i 后：

$$v_i=\left(\frac1{v_0}+\frac{N_i}{\sigma^2}\right)^{-1},\qquad
m_i=v_i\left(\frac{m_0}{v_0}+\frac{S_i}{\sigma^2}\right).$$

直觉：1/方差称为精度。先验精度和数据精度相加，后验均值按精度加权；越确定的信息权重越高。

例：m₀=0、v₀=1、σ²=1，某臂第一次 reward=2。更新后 v=1/2，m=(1/2)×2=1。第二次 reward=0，N=2、S=2，则 v=1/3、m=2/3。它不会直接把先验扔掉，也不把单个 noisy reward 当真实均值。

选臂采 `rng.normal(posterior_means, sqrt(posterior_variances))`。NumPy 的 scale 参数是标准差，因此必须开平方；源码已正确处理。不要把 `prior_variance` 与 `noise_variance` 混为一谈：前者是对未知均值的先验不确定性，后者是已知的观测噪声。选臂 O(K)，更新 O(1)。

## 四、接口追踪：从一个 Gaussian 配置到 CSV

以 `configs/gaussian_algorithms_smoke.json` 为例：3 个臂、5 个策略、T=100、seeds=[0,1]，共 10 次独立实验。

1. `load_config` 读 JSON；`normalize_config` 将 horizon 变成列表，统一算法字典格式。
2. `main` 先对整个 batch 做参数、兼容性与噪声模型预校验，再检查 `results/gaussian_algorithms_smoke` 的配置身份并写快照，然后循环 5×1×2 个组合。
3. 每次 `run_single_experiment` 派生两个 RNG；`create_environment` 创建三个同方差 Gaussian 臂。
4. `validate_algorithm_environment` 拒绝 Bernoulli 专用算法；`create_algorithm` 按名字构造类。
5. 每轮执行公共接口，产生 100 行记录；运行时检查计数、奖励、regret 和特定算法内部状态。
6. `save_records` 保存 10 个 CSV；分析阶段可读取它们，但现有 `plot_benchmarks.py` 的 main 只固定读取旧三组 benchmark，并不会自动发现这个 Gaussian 目录。

这也解释了为什么“新增算法 smoke 跑通”和“新版本完整画图分析”是不同的交付项目。

## 五、最容易被问到的 12 个问题

| 追问 | 应答要点 |
|---|---|
| 为什么要有 Random？ | 给出不学习基线，还能用解析期望检查整个实验链。 |
| regret 为什么用真实均值，算不算作弊？ | 真实均值只进入评估；策略只接收动作和观测奖励。 |
| regret 每步能否负？ | 此处 pseudo-regret 不会负；基于 realized reward 的另一指标可能负。 |
| 固定 ε-Greedy 能否停止探索？ | ε>0 时不会，所以保留长期探索成本。 |
| ETC 锁定后为何继续更新？ | 保留真实观测统计，便于一致性检查；并不代表重新决策。 |
| UCB-V 是否总比 UCB1 好？ | 不是；方差项与范围修正共同作用，有限预算常数很重要。 |
| MOSS 是否 anytime？ | 当前实现需要 T；改变 T 可能改变前缀动作。 |
| TS 是否抽下一次奖励？ | 抽未知均值的后验样本，再选该样本最大的臂。 |
| 有 Gaussian 环境就能跑所有算法吗？ | 不行；有界性、似然模型、噪声参数必须匹配。 |
| 两个 RNG 是否保证算法收到一样奖励？ | 保证随机流隔离；动作和分布不同，实际奖励仍会不同。 |
| 263 项测试通过是否证明能发布？ | 本次已补正式实验与干净环境验证；测试仍不等于数学证明，Git 发布状态也要单独确认。 |
| 新增算法要改哪里？ | 类、工厂、兼容性、测试、配置、文档；若保留 runner 特定检查也要接入。 |

## 六、练习方式与最小演示

第一遍只沿 15 分钟表讲，允许看文件。第二遍不看稿，用一个三臂例子讲公共循环，再凭记忆比较三个家族：显式探索、乐观评分、后验采样。第三遍让听众任意问上表问题。

现场只演示两条轻量命令，避免拿长 benchmark 占用讲解时间：

```bash
python -m pytest -q
python run.py --config configs/gaussian_algorithms_smoke.json
```

会出现少量未最常选中最优臂的 warning，短预算下不自动代表 bug。预先确认结果目录没有不同配置快照；演示时不执行会全删 results/figures 的旧 `reproduce.sh`。

合格标准：你能不看稿说清十策略的区别，准确解释 Gaussian std 与 variance，追踪一轮反馈到 CSV，指出现有证据能支持和不能支持的结论，并能解释至少一个边界修复及其回归测试。重点是掌握真实实现，而不是背诵十个名字。
